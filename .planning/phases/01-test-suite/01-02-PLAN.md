```yaml
    - name: Build Catch2 Tests
      run: |
        cd solvers/acoustics
        make tests
      env:
        LIBP_COVERAGE: 1

    - name: Run Catch2 Tests
      run: |
        cd solvers/acoustics
        mpirun --oversubscribe -np 1 ./acousticsTests
```

Rationale for each line:
- Two separate steps (Build vs. Run) so a link failure and an assertion failure surface as distinct CI step failures in the PR check (better blame attribution).
- `cd solvers/acoustics` because `make tests` is defined in the solver subdirectory's makefile (contrast with `make test` which is invoked from the repo root per the existing Test step).
- `LIBP_COVERAGE: 1` on the Build step mirrors the earlier Build step's env; this ensures the test objects are compiled with `--coverage -fprofile-abs-path` (same as `libacoustics.a`), so coverage instrumentation is consistent across the binary.
- The Run step does not need `LIBP_COVERAGE: 1` as an env var (coverage flags are a build-time concern), but including it would not hurt either; omitted here for minimalism matching the Build step convention.
- `mpirun --oversubscribe -np 1` per Claude's Discretion in CONTEXT.md (match the Python runner's convention for single-rank unit tests; all 4 unit tests and all 4 BC smoke tests are single-rank).

- Keep one blank line between the two new steps (matching the existing pattern where each step is visually separated).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> repo source | CI runner executes code from the repository; a malicious PR could in principle alter workflow YAML. Standard GitHub security model applies. |
| CI step shell commands | Each `run: |` block is a bash script running with `LIBP_COVERAGE=1` in the runner's ephemeral environment. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-06 | Tampering | `.github/workflows/build.yml` edit (Task 1) | mitigate | Workflow changes are visible in PR diff and subject to repo code review. No secrets are added (inherits only `GITHUB_TOKEN` which is already available). The new steps do not download or execute third-party code at CI time (Catch2 is vendored via Plan 01). |
| T-1-07 | Elevation of Privilege | CI step running `mpirun` as root | accept | Default GitHub Actions runners do not run as root; `mpirun` executes as the runner user. No privilege escalation path. Accept. |
| T-1-08 | Information Disclosure | Catch2 output printing LIBP_DIR paths in public CI logs | accept | Same exposure as the existing `acousticsMain` output captured by `make test`. No secrets. PR CI logs are public; this is the norm for open-source projects. Accept. |
| T-1-09 | Denial of Service | Catch2 step hanging indefinitely | accept | GitHub Actions enforces a 6-hour per-job timeout by default. The Python `make test` step has the same exposure. No explicit timeout added in Phase 1. Phase 2+ may add a `timeout-minutes: 30` field if runs become flaky. |
